lsStack

Problem this solves

Cryptic Linux tools delivering limited, poorly formatted, verbose reporting on individual system components.

How

Collection of intuitive commands providing enhanced, cleanly formatted, concise reporting on individual components or the complete system.

Why

Ease of use for those validating or expanding GPU centric workstation builds in a home or learning lab.

Features

Reports: what the number is, why it matters, and what to research next.

  • Verify - After a build or a new card, shows what seated properly and whether it came up correctly. Serials and evidence if a part has to go back.
  • Balance - Shows whether the PSU, PCIe slots, and RAM can carry the GPUs, and why nameplate ratings are best case.
  • PCIe links - Flags a GPU running below its rated lanes or generation, and explains how slot and CPU lanes decide it.
  • Expansion headroom - Shows the watts, lanes, and slots still free, so the next card is planned, not guessed.
  • Teach notes - Every warning says why it matters and what to research next.
  • Live watch - Temperatures and power draw while a job runs, to see how the design behaves under load.
  • Lab record - Each machine saved once, PSU and connectors included, so the next build starts from a known design.
  • Catalog - Add a card or PSU the shipped specs do not cover, and see which numbers matter while doing it.
  • Privilege - Most commands run without sudo. Fields that need root are named and explained.

Install

git clone https://github.com/lsStack-Lab/lsstack.git lsstack
cd lsstack
./scripts/install-user.sh

The installer links every ls command into $HOME/.local/bin, so they run from any directory. If the shell answers "command not found," that folder is not on your PATH yet. Add it:

export PATH="$HOME/.local/bin:$PATH"
